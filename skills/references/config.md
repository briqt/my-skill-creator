# 配置与用户数据

## 运行时数据目录

运行时文件默认集中放在 `~/.config/agent-skills/<skill-name>/`，不在 home 下另建隐藏目录。用语言的 home/path API 构造路径。注意 Windows 的 `~` 是当前 Windows 用户目录，WSL 中则是 Linux 用户目录，两者不会自动同步。工具已有的原生数据目录或用户指定的路径可以保留，但要写明，不强制迁移。

## 源码中提交什么

- `config.json`：配置模板，值为推荐默认值或类型零值，不含密钥。
- `config.schema.json`：JSON Schema，说明字段类型和用途。

不需要配置的工具不生成空模板和 schema。

## 加载与校验

1. Skill 源码目录下的 `.config.json`：只在显式启用开发模式时使用，被 gitignore 忽略，不按当前工作目录搜索。
2. `~/.config/agent-skills/<skill-name>/config.json`：标准位置。

按顺序使用找到的第一个文件，不合并多个文件。选中的文件无效时直接报错，不静默回退。安装包里的 `config.json` 只是模板，不是用户配置。只有依赖配置的命令才加载和校验配置；`--help`、`--version` 和配置初始化不要求配置已经存在。

## 初始化与迁移

- 提供非交互的 `config init` 或等价命令，从模板创建标准位置的配置和必要的目录。文件已存在时保留原文件，不覆盖。含必填凭据的模板只写空值，并提示需要填写哪些字段。
- 配置格式发生不兼容变化时，引入 `schema_version` 和明确的迁移路径：迁移前备份，转换后校验，用同目录临时文件原子替换。失败时保留原文件；遇到比当前程序更新的 schema 时报错，不降级覆盖。
- 缓存可以重建，不需要迁移。含凭据的文件用平台提供的权限机制限制访问。

## Profile

只在确实有多环境、多设备需求时才引入。选择顺序：`--profile` 参数 > config.json 中的 `active` 字段。没有选定或名称不存在时，列出可用的名称并给出修复方式，不静默改用其他目标。依赖 Profile 的命令在解析成功后、执行业务前，向 stderr 输出 `[profile: <name>]`；帮助、版本、初始化等不涉及 Profile 的命令不输出这一行。

## 配置错误

以非零退出码结束，错误信息包含实际搜索过的路径、出错的字段或原因，以及对应平台可以直接执行的修复命令（路径含空格时按目标 shell 正确引用）。只推荐程序真实支持的命令，示例中不写入凭据。
